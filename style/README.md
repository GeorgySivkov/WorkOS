# Корпус стиля (шаг 6.3)

Здесь лежит голос George по контекстам. Каждый файл `style/<context_id>.md` целиком
подаётся в промпт везде, где агент пишет от его имени.

| Файл          | Контекст (`work.contexts.id`) | Регистр |
|---------------|-------------------------------|---------|
| `infatica.md` | `infatica`                    | Slack и письма в Инфатике: свой, разговорный, по делу |
| `alfa.md`     | `alfa`                        | Банковская записка: вежливо, структурно, без панибратства |
| `linkedin.md` | (пока не контекст)            | Посты в LinkedIn: от первого лица, с историей и выводом |

## Как драфтер этим пользуется

1. `agents/drafter.py` берёт входящее, которому триаж поставил `needs_reply`.
2. Читает `style/<context_id>.md` этого письма или сообщения. Файла нет (например,
   `personal` или `consulting`), значит в промпт идут только жёсткие правила из кода
   (`agents.drafter.HARD_RULES`).
3. Кладёт корпус в системный промпт, следом последние три сообщения треда целиком.
4. Ответ модели проходит фильтр: длинные тире заменяются на запятую или дефис, даже если
   модель их всё-таки поставила.
5. В `events.meta.draft.style` записывается, какой файл был использован. Это нужно для
   проверки «готово, когда» из 6.3: сравнить acceptance rate черновиков писем до и после
   подключения корпуса (`agents.review` показывает его по неделям).

LinkedIn драфтер сейчас не пишет: файл лежит для будущих задач (посты, Unrote).

## Как наполнять

- Вставляй в раздел «Примеры» настоящие тексты, как они ушли: 5-15 штук на файл хватит.
  Лучше короткие и разные (ответ на вопрос, отказ, статус, просьба), чем один длинный.
- Перед примером одна строка: кому и в какой ситуации. Модель учится на контрасте.
- Чужие персональные данные, суммы и номера договоров из примеров убирай.
- Правила в начале файла правь смело: это и есть тот «ответ модели идёт в промпты руками»
  из воскресного разбора (6.1).
- Файл читается при каждом вызове, перезапуск не нужен. Держи каждый файл до ~15 КБ:
  он целиком уходит в каждый промпт.
